# Audit skill proyek KAR Labs

**26 skill terpasang, 26 berkas instruksi dibaca.** Semuanya dilacak Git di `.agents/skills/<nama>/SKILL.md`. Pemeriksaan path tidak menemukan `.agnets/skills/`. Pengelompokan SHA-256 atas isi 26 berkas tersebut tidak menemukan duplikat identik. Ada kesamaan topik antar-skill yang dijelaskan di bawah.

Inventaris ini memeriksa checkout dengan basis `a168e3b`. Katalog skill sesi menunjuk ke direktori proyek itu. `AGENTS.md` merujuk ke konteks bisnis serta alur build dan validasi. Berkas tersebut tidak memanggil skill per nama. `skills-lock.json` menyimpan sumber, commit, lokasi, dan hash **delapan** skill GSAP. Delapan belas skill lainnya dapat ditemukan langsung melalui katalog sesi dan Git. Build hanya menyalin aset situs dan halaman yang dihasilkan. Tidak ada proses Netlify yang menjalankan instruksi Markdown atau menjalankan skill pada browser pengunjung.

## Cara membaca bukti

Kolom terakhir membedakan bukti implementasi dari bukti pemanggilan skill. **R** merujuk ke laporan penyempurnaan yang menyebut tujuh skill per nama. **M** merujuk ke laporan motion yang menyebut keluarga GSAP, Motion, Lenis, dan anti-slop. Keduanya merupakan catatan pekerjaan terdahulu. Tagihan token, jumlah invokasi, dan urutan pemanggilan per sesi tidak tersedia dari repo. [Laporan penyempurnaan](REFINEMENT_SHOWROOM.md) dan [sistem motion](SISTEM_MOTION.md).

Semua baris di bawah berstatus **terpasang dan dibaca pada audit ini**. Kolom lingkup menyatakan apakah skill berlaku pada permintaan ini. “Audit” berarti instruksinya dipakai untuk mengevaluasi keputusan, dengan atau tanpa implementasi baru. “Dipakai” berarti aturan itu diterjemahkan ke pekerjaan konkret. “Disimpan” berarti fitur atau jenis hasil yang memerlukannya berada di luar permintaan.

## Ponytail dan keputusan lingkup

Skill menetapkan mode `full` sebagai default. Pemanggilan mengikuti nama skill pada permintaan atau sintaks `/ponytail lite|full|ultra` pada host yang mendukung perintah itu. Dokumentasinya juga menyebut “stop ponytail” atau “normal mode” untuk mengakhiri mode sesi. Dalam sesi Codex ini nama skill tersedia di katalog dan berkas instruksinya dapat dibaca langsung. Tidak ada layanan, kunci API, instalasi npm, maupun aset visual prasyarat. Objek yang diperiksa lebih dulu adalah permintaan, kode terkait, pemanggil, fixture, tes, serta risiko terhadap data atau kontrak yang sudah ada.

Urutan pemilihan solusi adalah pakai kembali implementasi proyek, pertimbangkan fitur platform dan dependensi terpasang, lalu tulis kode minimum yang memenuhi seluruh kebutuhan. Mode `lite` menyajikan opsi kecil, `full` menjalankan alur lengkap, dan `ultra` mempertanyakan tambahan dengan manfaat yang belum jelas. Untuk perombakan ini, satu perubahan templat harus menjangkau delapan rute, jalur build, dan uji yang terdampak. Mempertahankan komposisi lemah justru membiarkan tugas belum selesai. ## Konflik, rujukan, dan batas efektivitas

- **Mengapa penggunaan skill belum terlihat pada tampilan diam.** Perbandingan `git diff 1791e04 a168e3b -- public/portfolio.css` memperlihatkan delapan baris ditambah dan lima dihapus. Perubahannya mengatur kontrol untuk satu hasil, tinggi target sentuh, identitas View Transition, dan penghapusan parallax idle. Aturan geometri panggung, panel, dan bingkai tetap sama pada dua commit itu. Tes motion dapat lulus dan gerak bisa lebih responsif sementara komposisi pertama tetap terlihat serupa.
- **Cakupan audit.** Playbook `anti-ui-slop` membatasi temuan visual utama agar dapat ditindaklanjuti. Permintaan eksplisit untuk 12 kelompok hasil tetap mengatur laporan seluruh repo. Keluarga `antislop` membagi lapisan visual, bahasa, aksesibilitas dan responsivitas. `antislop-code` hanya memberi dasar untuk perubahan komentar.
- **Kedalaman vs aksesibilitas.** `frontend-design` memperbolehkan perubahan komposisi yang jelas. `antislop-human` dan `antislop-layoutmobile` mengharuskan kontrol tetap dapat dipakai saat gerak dikurangi atau hover tidak tersedia. Memperbesar amplitudo satu tween saja akan melewatkan kelompok pengguna tersebut.
- **Batas engine.** Skill GSAP, Motion, dan Lenis menawarkan pemilik berbeda bagi gerak, gesture, dan scroll. Registrasi paket npm dan pemasangan Markdown tidak menambah pengalaman visual. Bukti kontribusi yang bisa diulang adalah sumber runtime, kondisi media, tindakan pengguna, dan keadaan sesudah tindakan.
- **Referensi yang relevan.** Untuk review ini dibaca playbook audit, pola aksesibilitas, ringkasan WCAG, baseline web, dan panduan membedakan metrik lab dari data lapangan. [Playbook audit](../.agents/skills/anti-ui-slop/reference/audit.md), [pola aksesibilitas](../.agents/skills/antislop-human/references/A11Y-PATTERNS.md), [WCAG](../.agents/skills/antislop-human/references/WCAG.md), [baseline web](../.agents/skills/antislop-ui/references/WEB-BASELINE.md), [Core Web Vitals](../.agents/skills/antislop-ui/references/CORE-WEB-VITALS.md).
- **Batas atribusi.** Kenaikan kualitas visual dapat diperiksa dengan pasangan screenshot dan alur demo yang sama. Atribusi persentase peningkatan kepada skill tertentu memerlukan eksperimen pembanding. Git tidak menyediakan eksperimen tersebut. Seluruh skill tetap tersimpan untuk tugas lain.
